# Change request analysis (Steps 1 and 2)

Save the completed copy as `docs/a4/analysis.md`.

## Step 1: Analysis of each request

Copy this block for each request in your packet.

### A4-CR-n

| Item | Answer |
| --- | --- |
| Quality and softgoal | Quality concerned, and the goal model ID of the softgoal |
| Obstacle | What keeps the goal from being satisfied |
| Likelihood | High, Medium or Low, with the evidence |
| Criticality | Major or Minor, with the evidence |
| Classification | Change of intent, change of approach, or defect. Quote the spec text that supports the classification |
| Affected artifacts | Requirements, spec items, code components and tests that would have to change |
| Side effect | New obstacle the change would create for a different goal, with likelihood and criticality. Write "none found" if the team found no side effect |
| Feasible in the prototype | Yes, Partly or No, with the reason |
| Assumptions | Each ambiguity in the request and the assumption the team made |
